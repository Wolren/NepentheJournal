## P0 — Functional or high-visibility issues found in audit

### 1. Timeline events added in a NEW session editor become orphaned on save (data loss)

`SessionEditorScreen.kt:362` passes a provisional id to the events section:

```kotlin
sessionId = sessionToEdit?.id ?: "session:${currentTimeMillis()}"
```

`SessionEventsSection.kt:49` immediately persists every event with that provisional `sessionId` via `repo.upsertTimelineEvent(newEvent)`. On save, `SessionEditorScreen.kt:136` computes a NEW id (`"session:${now}"`) and only re-parents **doses** (line 179: `dose.copy(sessionId = sessionId)`). Timeline events are never re-parented.

Result: for new sessions, every event added in the editor keeps the provisional `sessionId`, the saved session has a different id, and `eventsForSession(session.id)` returns nothing. Events are invisible in the timeline after save, and they linger as orphaned rows forever. In edit mode the id is stable so the bug hides.

Secondary consequence: events are persisted immediately, so discarding a new-session draft (Discard dialog) still leaves the orphaned events in the store.

Fix: in `saveSession()`, re-parent events the same way doses are re-parented (`event.copy(sessionId = sessionId)` + upsert), and delete provisional orphans (`repo.eventsForSession(provisionalId)` where provisionalId != sessionId). Or defer event persistence until save.

### 2. Date formats are inconsistent across screens (violates the "DD Mon YYYY" rule)

| Screen | Location | Format shown |
|--------|----------|--------------|
| SessionTimelineScreen | :91 | `31 Jul 2026` ✅ |
| SessionDoseSection | :137 | `31 Jul 2026 15:30` ✅ |
| TimeField (editor) | :57-59 | `17 January 2026` (full month) |
| DashboardScreen | :290-294 | `Friday, July 31, 2026` (weekday + full month) |
| CalendarScreen | :269 | `2026-07-31` (raw ISO via `"${selectedDate}"`) |
| SubstanceDetailScreen | :489 | `7/31` (numeric MM/DD) |

Two numeric formats, two long formats, one short format. The user's stated convention is uniform `DD Mon YYYY`.

Fix: add `formatDateFull` / `formatDateCompact` to `TimeFormat.kt` and replace all six call sites. Calendar and dose history are the worst offenders.

### 3. Delete affordance on session cards is dead code

`SessionCard.kt:35` accepts `onDelete: () -> Unit` but never renders it — the only action in the card is the Edit icon. `SessionListScreen.kt:191` wires `onDelete = { showDeleteConfirm = session.id }`, so the entire delete-confirm path in the list screen is unreachable. Users must open the editor and delete from there.

The established convention (from the UI polish sessions) is edit + delete as visible icon buttons on session cards. Either add the Delete icon button next to Edit in `SessionCard.kt`, or remove the dead parameter and the dead dialog state.

### 4. "Close" icon used as the selected-state indicator in filter dropdowns

`SessionListScreen.kt:106,128` and `SubstanceScreen.kt:96,122`: selected items show an X glyph (`Icons.Default.Close`) inside a primary-colored box. A close glyph reads as "remove / clear", not "selected" — the exact opposite semantic. This appears both in the "Clear filters" / "All categories" rows and every selected substance/category row.

Fix: swap to `Icons.Default.Check` (checkmark in a filled square is the universal selected pattern). One-line change per site, four sites.

### 5. White text on AdaptiveColors chips fails WCAG contrast in both themes

`AdaptiveColors.kt`: light variant lightness 40-60%, dark variant 25-45%. `SessionCard.kt:154` (dose chips), `TimelineBar.kt:108` (substance chips) and the live dose cards hardcode `Color.White` text on those backgrounds.

Contrast math (white vs. background luminance):
- Light variant at L=45%: ~2.1:1
- Dark variant at L=45%: ~2.1:1, at L=25%: ~3.5:1
- WCAG AA for normal text: 4.5:1

Every hue lands well below the threshold. The dose chips and timeline substance chips are illegible-ish on light theme and marginal on dark theme.

Fix: replicate the `TagColors.foreground()` pattern — pick black or white by `luminance()` on the actual color instead of hardcoding white. `TagColors.kt:44-48` already has the exact helper.

## P1 — Consistency and polish

### 6. SearchOverlay has no DesktopScrollbar

`SearchOverlay.kt` renders a LazyColumn but never adds `DesktopScrollbar(scrollState)`. Every other scrollable list screen (Dashboard, Sessions, Substances, Safer, Settings) has one. A search result list can be long; invisible scrolling on desktop.

### 7. Three affordances for the same action on the Substances tab

`SubstanceScreen.kt`: FAB (line 216) + bottom-of-list "Add custom substance" button (line 201) + empty-state button (lines 150, 170). The FAB and the bottom list button are redundant on desktop. Keep the FAB (or the bottom button) and drop the other.

### 8. TopSubstancesChart bar layout reads backwards

`DashboardCharts.kt:137-173`: the proportional bar renders to the LEFT of the substance name with `weight(fraction)`, name with `weight(1f)`. Long names crush the bar to a sliver; short names stretch it. Standard ranking viz puts the label in a fixed column and the bar right of it, or the bar as a full-width underline (which the tolerance bars in this app already do well).

Suggested fix: fixed-width name column (or `Row` with name + count, then a 6dp full-width bar underneath, matching the ToleranceCard visual language).

### 9. Theme: background opacity edit state starts at 50%

`SettingsScreen.kt:62`: `editBgOpacity` initializes to `0.5f` while `ThemeDefaults` uses `0.3f`. A user who opens Custom and types a background image path without touching the slider gets a jump to 50% on Apply. Initialize from `themeConfig.backgroundOpacity`.

### 10. "Ingestion History" card is a placeholder

`SubstanceDetailScreen.kt:435-443`: the section renders only "N doses recorded" text. Either give it a real mini chart (the companion screen already has the full visualization) or remove the card and let Dose History + Tolerance timeline carry the content.

### 11. Primary action "Save" is a TextButton

`SessionEditorScreen.kt:267` uses `AppTextButton` for the editor's primary action while delete is a full IconButton. M3 hierarchy suggests a filled button for the primary action, especially on desktop where the editor is the most-used screen.

### 12. Filter dropdowns close on every toggle

`SessionListScreen.kt:122-124` and `SubstanceScreen.kt:115-118`: each click toggles one item AND closes the menu, so multi-select requires reopen + scroll per item. Keep the menu open until dismissed or a "Done" row is clicked; "Clear filters" can stay immediate.

## P2 — Fine taste and mobile polish

### 13. Tiny font sizes below the readability floor
- `ActivityHeatmap.kt:168,175` — 9sp date labels
- `TimelineBar.kt:117` — 10sp row labels, 11sp scrub label
- `AffinityBar` in `PharmacologySection.kt:260` — `labelSmall * 0.75` ≈ 9sp

These are secondary annotations on desktop, but on mobile 9-10sp is genuinely hard to read. Consider a 10sp floor and `fontScale` respect (the theme already has `fontScale` — these fixed-size texts ignore it).

### 14. Monospace style exists but is unused for data
`Typography.kt:114` defines `monospaceStyle` ("dose amounts, hex codes, timestamps") but no screen uses it. Dose amounts in cards and the duration total are the obvious candidates — monospace digits make dosage values scannable.

### 15. Numeric fields lack numeric keyboards on mobile
`DoseEditDialog.kt` amount field, `SessionDemographicsSection.kt` age/height/weight, `SessionRatingSection` chips are fine, but amount/age/height/weight use default keyboards. Add `KeyboardType.Decimal` / `KeyboardType.Number` (the import already exists in SettingsScreen).

### 16. Touch targets below 48dp
FilterChips at 32dp (`SessionRatingSection.kt:31,47`, `EditorInlineEventCard.kt:59`), IconButtons at 28dp in cards (`SessionCard.kt:123`, `EditorInlineEventCard.kt:151`). Fine on desktop, cramped on Android. At minimum keep the 48dp minimum bounding box on mobile via `minimumInteractiveComponentSize`.

### 17. Section header styles differ per screen
Dashboard section headers use `titleLarge` ("Tolerance Overview"), substance detail uses `titleSmall` primary-colored inside cards, settings uses `titleMedium` in collapsible cards, editor uses divider + `titleMedium`. Each is internally consistent; the hierarchy between screens drifts. Pick one pattern for "section title" (suggestion: `titleSmall` + primary for carded content, `titleLarge` only for page-level groups) and apply it.

### 18. Hardcoded semantic colors bypass the theme
- `DashboardScreen.kt:241,247` — MEDIUM tolerance `Color(0xFFFF9800)` hardcoded twice
- `DashboardCharts.kt:116-120` — top-substances purple ramp hardcoded (acceptable as a deliberate ramp, but it duplicates the theme primary family)

Tolerance MEDIUM should come from a shared semantic token (like `routeColor` / `substanceClassColor` live in `RouteColors.kt`) so light/dark variants can differ.

### 19. AdaptiveColors cache is an unsynchronized global map
`AdaptiveColors.kt:27` — `mutableMapOf` mutated from recomposition threads. The computation is idempotent so the risk is a lost update, not corruption, but a `ConcurrentHashMap` costs nothing and removes the smell.

### 20. Tab labels drift from feature names
`App.kt:84-88`: "Board", "Sessions", "Drugs", "Safe", "Settings" vs. internal names Dashboard / Substances / Safer Use. Deliberate per earlier sessions, but "Drugs" and "Safe" are the two that read informal next to "Settings". Worth a deliberate decision, not an accident.

### 21. Search results could show type counts better
`SearchOverlay.kt:119-153` groups by type with icon + count — good. The result cards show the raw `entityType` string ("session", "substance") at the trailing edge instead of the grouped label; harmless duplication of the header. Cosmetic.

## Strengths (keep, don't regress)

- App shell: transparent top bar only on Sessions, keyboard shortcuts (Ctrl+F, Ctrl+N), Esc-to-back, back-handler stack, recovery dialog, backup-on-close
- Theme system: `ThemeConfig` derived containers, contrast-aware `onPrimary` etc., cached scheme computation, font/animation scales, background image layer
- Buttons: press-scale on all five variants, hover elevation on cards, tooltips on desktop icons
- Scrollbars: 6dp, primary at 20/40%, 3dp corners, on every main list screen
- Session identity: adaptive per-substance colors, route color dots/indicators, class chips, gradient dosage bands
- Duration visualization: ggplot2-style curve with grid, area fill, phase tiles, afterglow strip, total duration bar
- Pharmacology: log-scale affinity bars with median dot, species/source chips, strength legend
- Calendar / heatmap / timeline bar: all single-Canvas implementations, precomputed cells, drag-scrub with time readout
- Live session: circular timer, phase chips, quick dose/mood dialogs, crisis button, auto-scroll, interaction banner
- Empty states everywhere with icon + title + action hint
- Copy: "No ads. No subscriptions. No tracking. Your data is yours."

## Verdict

The app has a genuinely strong visual identity and some of the best custom Compose Canvas work in the codebase (duration curve, affinity bars, timeline bar). The audit found one real data bug (orphaned events), one rule violation that shows on nearly every screen (date formats), and a cluster of small consistency issues. None of the P1/P2 items require architecture change; they are single-file polish passes. The fastest win per hour is the date format centralization plus the four icon/contrast swaps.
